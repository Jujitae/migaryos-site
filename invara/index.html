INVARA — free local task instructions

This is a check plan, not a verification result. Use your existing local coding assistant (Codex, Claude Code, or another assistant that can run local commands). No code upload or payment is required by this workflow.

1. Before changing the project, confirm that you can run local commands on the computer holding it. Python 3.12+ is required. Read the public INVARA README and AI Agent Quickstart at https://github.com/Jujitae/invara. Use the published package and record its actual version. Do not assume a newer release or kit has been published.

2. Inspect the existing project without changing it. Identify the actual files that must stay unchanged and existing runnable completion checks. Explain in plain language what each check observes and what it misses. Do not invent a passing command, replace a real check with an always-successful command, or silently weaken the requested conditions.

3. Show me the proposed task contract, protected files, existing check commands and any required human decision. Ask me to confirm that this expresses the task. If no suitable existing check, trustworthy pre-work state or local execution access is available, stop and name what is missing. Do not invent evidence or retroactively seal a before state for work that has already happened.

4. Use the local INVARA CLI. With uv installed, start with `uvx invara list`. Alternatively, install in an appropriate local Python environment with `python -m pip install invara`, then use `invara list`. Follow the published contract schema; replace placeholders with the actual agreed task file and task ID. Seal BEFORE editing: `uvx invara seal <task.json>` (or `invara seal <task.json>` for the persistent install). A plan alone is not a seal or a check.

5. Make only the agreed changes. Afterwards run `uvx invara judge <task_id> --commit` (or `invara judge <task_id> --commit`). Preserve the exact output, actual tool version and evidence location locally. Commands run with my permissions and may access the network. INVARA is not a sandbox.

6. Read the original verdict field, not just the process exit code. PASS: checked conditions met within the declared scope. BLOCK: a condition was broken. UNVERIFIABLE: could not check. HUMAN_REVIEW: needs a person, even when the exit code is 0. An engine error or refusal is not a verdict. Never rename a non-PASS result as success. Do not treat your own completion claim as evidence or a PASS as permission to publish or deploy.

7. Give me a plain-language handoff: task and declared scope; original verdict; what was and was not checked; original evidence location; actual tool version; and instructions for the recipient to recheck. A stored-record replay is not a new execution. Keep reports on my computer. If something failed, preserve the result, identify the broken or missing condition, and agree on a next step before changing the contract or trying again.

Keep the error locally. Check Python, the installed version and the public quickstart. An error or refusal is not a verdict, and retrying is not evidence that it worked.

Your data and optional measurement

There is no account, upload field or remote model in this page. Your optional note and draft stay in memory until you clear or reload the page. Copy and download happen only when you request them. We use no cookies or browser storage.
